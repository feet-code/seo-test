Teams repeatedly ask for missing client inputs without a shared definition of what is complete, which blocks delivery while making the agency look late. The recurring failures are usually process-design problems rather than motivation problems. For small creative, design, and digital agencies, these are the mistakes worth finding before buying or building software.


### 1. Requesting vague buckets such as all website content

This usually survives because the workflow records activity but not the decision that activity was meant to produce. Add **Requested asset** at the point of work and enforce this guardrail: One agency owner coordinates reminders When the exception occurs, keep it visible instead of repairing it privately in email.

### 2. Marking a file received before checking usability

This usually survives because the workflow records activity but not the decision that activity was meant to produce. Add **Acceptance criteria** at the point of work and enforce this guardrail: Sensitive credentials use an appropriate secure channel When the exception occurs, keep it visible instead of repairing it privately in email.

### 3. Sending reminders from multiple teammates

This usually survives because the workflow records activity but not the decision that activity was meant to produce. Add **Example or format** at the point of work and enforce this guardrail: Delivery impacts are surfaced when required inputs slip When the exception occurs, keep it visible instead of repairing it privately in email.

### 4. Keeping the delivery date unchanged after a critical input slips

This usually survives because the workflow records activity but not the decision that activity was meant to produce. Add **Client owner** at the point of work and enforce this guardrail: Every request includes an example and acceptance criteria When the exception occurs, keep it visible instead of repairing it privately in email.

## Audit five recent records

Pick five completed or abandoned examples and ask:

- Can we reconstruct client and project without asking the original owner?
- Can we reconstruct requested asset without asking the original owner?
- Can we reconstruct acceptance criteria without asking the original owner?
- Can we reconstruct example or format without asking the original owner?
- Can we reconstruct client owner without asking the original owner?

If the answer is no, improve the capture point rather than adding a later reporting step. Reports cannot recover decisions that were never recorded.

## Use mistakes as software requirements

Turn every frequent failure into a testable requirement. “Better visibility” is vague; “show every record with no owner or next date” can be tested. “More automation” is vague; “stop reminders after the completion condition is recorded” can be tested.
