A checklist for client asset collection and missing content tracking for agencies should prevent missing decisions, not merely prove that somebody clicked boxes. The checklist below is designed for small creative, design, and digital agencies and centers on one result: **the agency receives usable client inputs by the date required for the dependent deliverable**.

## Before the work starts

- Confirm Client and project
- Confirm Requested asset
- Confirm Acceptance criteria
- Confirm Example or format

Also name the owner and the expected completion condition. If either is unknown, the work is not ready to enter the active queue.

## While the work is moving

- Update Define each required input
- Update Send one organized request
- Update Validate received material
- Update Escalate blockers
- Update Release the dependent work

Every update should change a decision. Notes such as “followed up” are weak unless they also include the channel, result, next date, and owner.

## Before marking it complete

- Verify Client owner
- Verify Required-by date
- Verify Dependent deliverable
- Verify Received link
- Verify Validation status

Confirm that the actual outcome—not just an activity—has been recorded. If the process ended early, use a closed reason rather than deleting the record.

## Copy-and-paste weekly review

- [ ] Review records where an input is missing at the first reminder date
- [ ] Review records where a received file fails its acceptance criteria
- [ ] Review records where a critical input threatens the dependent delivery date

- [ ] Check for requesting vague buckets such as all website content
- [ ] Check for marking a file received before checking usability
- [ ] Check for sending reminders from multiple teammates
- [ ] Check for keeping the delivery date unchanged after a critical input slips

## Make the checklist measurable

Choose one metric before the next cycle. Good options for this workflow are Usable-on-first-receipt rate, Client-input delay, Blocked deliverable count. A checklist that never changes a metric or prevents a known failure mode is probably administrative overhead.

## Assign ownership and escalation

Put one role—not a group—next to every item that can remain open. Define a backup owner and an escalation time for work that affects a customer, client, participant, or delivery promise. During review, separate **not started**, **waiting on someone**, and **failed validation**; those states need different actions. If a checklist item repeatedly waits on the same dependency, redesign the intake or handoff instead of adding more reminder boxes.
