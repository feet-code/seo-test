Examples make client asset collection and missing content tracking for agencies easier to design because they reveal where a neat diagram meets messy work. The scenarios below are not claims about a particular company; they are test cases small creative, design, and digital agencies can run against a template or software trial.

### Scenario 1: A logo arrives as a low-resolution screenshot instead of a source file

Create the record before the first follow-up. Capture Client and project, Requested asset, Acceptance criteria, then move it through define each required input and send one organized request. If an input is missing at the first reminder date, do not improvise in a private message; assign the exception, set a review date, and preserve the evidence needed for the next decision. Close with an explicit outcome and reason. ### Scenario 2: Six page drafts are complete but legal copy has no client owner

Create the record before the first follow-up. Capture Requested asset, Acceptance criteria, Example or format, then move it through define each required input and send one organized request. If a received file fails its acceptance criteria, do not improvise in a private message; assign the exception, set a review date, and preserve the evidence needed for the next decision. Close with an explicit outcome and reason. ### Scenario 3: Credentials are sent in an unsafe channel and must be re-requested securely

Create the record before the first follow-up. Capture Acceptance criteria, Example or format, Client owner, then move it through define each required input and send one organized request. If a critical input threatens the dependent delivery date, do not improvise in a private message; assign the exception, set a review date, and preserve the evidence needed for the next decision. Close with an explicit outcome and reason.

## Debrief each scenario

After running a scenario, ask:

- Did the record make every request includes an example and acceptance criteria?
- Did the record make one agency owner coordinates reminders?
- Did the record make sensitive credentials use an appropriate secure channel?
- Did the record make delivery impacts are surfaced when required inputs slip?

Also check whether a new teammate could identify the owner, next action, and finish condition without opening another system.

## Convert scenarios into acceptance tests

Use the normal case, waiting case, and closed-without-completion case in every software demo. Require the vendor—or your own prototype—to show the full workflow rather than isolated feature screens. Export the resulting records and verify that the status history remains understandable.
