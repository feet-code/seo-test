The most useful land survey field crew readiness template is a small operating record. It should answer what is happening, who owns it, what evidence exists, and when the next decision occurs. This structure works in a spreadsheet, database, or focused application.

## Recommended record fields

| Field | Why it exists | Update point |
|---|---|---|
| Client project parcel and task | Prevents the record from depending on memory or an inbox search | Review project scope and requested deliverable |
| Scope deliverable and due date | Prevents the record from depending on memory or an inbox search | Assemble parcel research control and prior records |
| Deeds plats control and prior survey files | Prevents the record from depending on memory or an inbox search | Confirm access hazards schedule and client contact |
| Coordinate system data files and version | Prevents the record from depending on memory or an inbox search | Match crew equipment and digital files |
| Access permission contact and timing | Prevents the record from depending on memory or an inbox search | Release the versioned field packet and acknowledge receipt |
| Hazards utility traffic and site conditions | Prevents the record from depending on memory or an inbox search | Review project scope and requested deliverable |
| Crew roles equipment and calibration | Prevents the record from depending on memory or an inbox search | Assemble parcel research control and prior records |
| Office reviewer release and crew acknowledgment | Prevents the record from depending on memory or an inbox search | Confirm access hazards schedule and client contact |

## Suggested statuses

Use workflow statuses that describe reality: **Review Project Scope And Requested Deliverable → Assemble Parcel Research Control And Prior Records → Confirm Access Hazards Schedule And Client Contact → Match Crew Equipment And Digital Files → Release The Versioned Field Packet And Acknowledge Receipt**. Add **Waiting** only when you also capture a waiting reason and review date. Add **Closed—Not Completed** when an item legitimately ends without the desired outcome.

## Follow-up rules

- When a field task enters the schedule, assign a next action and review date.
- When scope access research or file version changes, assign a next action and review date.
- When the crew reports a missing or conflicting prerequisite, assign a next action and review date.

Avoid reminders with no stop condition. A rule should say when it starts, who receives it, what counts as a response, and when a person should take over.

## Example records

- A boundary job lacks the referenced plat
- A gate contact is unavailable on survey morning
- A revised control file does not reach the data collector

For each example, write the current status, next action, owner, and supporting evidence. This makes the template testable with real work rather than idealized sample data.

## Quality-control rules

- Every open field assignment needs one owner and a next review time
- Completion requires recorded evidence that every survey field assignment has current office research, site permissions, technical files, equipment, crew capability, and explicit release
- Automated reminders stop after verified completion or a documented closed reason
- Keep the survey proposal, project, parcel, crew, field-data, CAD, review, and billing platform as the system of record; only necessary coordination data belongs here

Before adding automation, run the template manually for a week. Remove ambiguous fields and confirm that two different users classify the same situation the same way. Consistency matters more than having a long form.
