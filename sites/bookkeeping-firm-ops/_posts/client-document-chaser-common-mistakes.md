Client requests are repeated across email threads without a clear item-level status, acceptance check, or effect on the close schedule. The recurring failures are usually process-design problems rather than motivation problems. For small bookkeeping firms and client accounting service teams, these are the mistakes worth finding before buying or building software.


### 1. Requesting documents in one vague paragraph

This usually survives because the workflow records activity but not the decision that activity was meant to produce. Add **Requested item** at the point of work and enforce this guardrail: Every request names the exact item and period When the exception occurs, keep it visible instead of repairing it privately in email.

### 2. Marking an upload complete before checking the period and account

This usually survives because the workflow records activity but not the decision that activity was meant to produce. Add **Purpose** at the point of work and enforce this guardrail: One firm owner coordinates reminders When the exception occurs, keep it visible instead of repairing it privately in email.

### 3. Sending duplicate reminders from different staff

This usually survives because the workflow records activity but not the decision that activity was meant to produce. Add **Secure upload location** at the point of work and enforce this guardrail: Received is distinct from reviewed and accepted When the exception occurs, keep it visible instead of repairing it privately in email.

### 4. Failing to show which deliverable a missing item blocks

This usually survives because the workflow records activity but not the decision that activity was meant to produce. Add **Client owner** at the point of work and enforce this guardrail: Sensitive files use an approved secure channel When the exception occurs, keep it visible instead of repairing it privately in email.

## Audit five recent records

Pick five completed or abandoned examples and ask:

- Can we reconstruct client and period without asking the original owner?
- Can we reconstruct requested item without asking the original owner?
- Can we reconstruct purpose without asking the original owner?
- Can we reconstruct secure upload location without asking the original owner?
- Can we reconstruct client owner without asking the original owner?

If the answer is no, improve the capture point rather than adding a later reporting step. Reports cannot recover decisions that were never recorded.

## Use mistakes as software requirements

Turn every frequent failure into a testable requirement. “Better visibility” is vague; “show every record with no owner or next date” can be tested. “More automation” is vague; “stop reminders after the completion condition is recorded” can be tested.
