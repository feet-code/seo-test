Examples make bookkeeping client document collection and reminder tracking easier to design because they reveal where a neat diagram meets messy work. The scenarios below are not claims about a particular company; they are test cases small bookkeeping firms and client accounting service teams can run against a template or software trial.

### Scenario 1: A client uploads one bank statement but omits the second account

Create the record before the first follow-up. Capture Client and period, Requested item, Purpose, then move it through create the period request list and send the secure itemized request. If an item remains missing at the reminder date, do not improvise in a private message; assign the exception, set a review date, and preserve the evidence needed for the next decision. Close with an explicit outcome and reason. ### Scenario 2: A receipt export covers the wrong month

Create the record before the first follow-up. Capture Requested item, Purpose, Secure upload location, then move it through create the period request list and send the secure itemized request. If a file is unreadable, incomplete, or for the wrong period, do not improvise in a private message; assign the exception, set a review date, and preserve the evidence needed for the next decision. Close with an explicit outcome and reason. ### Scenario 3: A transaction explanation arrives in email but is not attached to the open request

Create the record before the first follow-up. Capture Purpose, Secure upload location, Client owner, then move it through create the period request list and send the secure itemized request. If a missing item threatens the agreed delivery date, do not improvise in a private message; assign the exception, set a review date, and preserve the evidence needed for the next decision. Close with an explicit outcome and reason.

## Debrief each scenario

After running a scenario, ask:

- Did the record make sensitive files use an approved secure channel?
- Did the record make every request names the exact item and period?
- Did the record make one firm owner coordinates reminders?
- Did the record make received is distinct from reviewed and accepted?

Also check whether a new teammate could identify the owner, next action, and finish condition without opening another system.

## Convert scenarios into acceptance tests

Use the normal case, waiting case, and closed-without-completion case in every software demo. Require the vendor—or your own prototype—to show the full workflow rather than isolated feature screens. Export the resulting records and verify that the status history remains understandable.
