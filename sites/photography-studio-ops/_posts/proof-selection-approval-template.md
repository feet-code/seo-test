The most useful photography client proof selection and approval template is a small operating record. It should answer what is happening, who owns it, what evidence exists, and when the next decision occurs. This structure works in a spreadsheet, database, or focused application.

## Recommended record fields

| Field | Why it exists | Update point |
|---|---|---|
| Client, shoot, and gallery | Prevents the record from depending on memory or an inbox search | Publish the controlled proof set |
| Proof-set version | Prevents the record from depending on memory or an inbox search | Collect image-specific selections and comments |
| Image identifier | Prevents the record from depending on memory or an inbox search | Confirm product, usage, and retouching scope |
| Selection status and intended output | Prevents the record from depending on memory or an inbox search | Return revisions for approval when required |
| Client comment | Prevents the record from depending on memory or an inbox search | Freeze approved finals and release production |

| Authorized approver and decision time | Prevents the record from depending on memory or an inbox search | Collect image-specific selections and comments |

## Suggested statuses

Use workflow statuses that describe reality: **Publish The Controlled Proof Set → Collect Image Specific Selections And Comments → Confirm Product Usage And Retouching Scope → Return Revisions For Approval When Required → Freeze Approved Finals And Release Production**. Add **Waiting** only when you also capture a waiting reason and review date. Add **Closed—Not Completed** when an item legitimately ends without the desired outcome.

## Follow-up rules

- When a proof deadline approaches without submitted selections, assign a next action and review date.
- When multiple reviewers provide conflicting decisions, assign a next action and review date.
- When a retouched revision or product choice changes the selected output, assign a next action and review date.

Avoid reminders with no stop condition. A rule should say when it starts, who receives it, what counts as a response, and when a person should take over.

## Example records

- A commercial client selects image 104 but references an old filename
- Two family members submit different album favorites
- A crop revision needs approval before a print order

For each example, write the current status, next action, owner, and supporting evidence. This makes the template testable with real work rather than idealized sample data.

## Quality-control rules

- Every open photo proof decision needs one owner and a next review time
- Completion requires recorded evidence that every client selection and approval identifies the exact images, revision, intended output, approver, and final decision
- Automated reminders stop after verified completion or a documented closed reason
- Keep the studio CRM, contract, gallery, asset, and delivery platform as the system of record; only necessary coordination data belongs here

Before adding automation, run the template manually for a week. Remove ambiguous fields and confirm that two different users classify the same situation the same way. Consistency matters more than having a long form.
