A checklist for dance studio recital readiness tracking should prevent missing decisions, not merely prove that somebody clicked boxes. The checklist below is designed for independent dance studios producing multi-class recitals and centers on one result: **every recital number and performer reaches show day with approved music, participation, costume, call time, quick-change, volunteer, and backstage dependencies verified**.

## Before the work starts

- Confirm Recital show number class and teacher
- Confirm Performer participation and guardian contact
- Confirm Music file version duration and cue
- Confirm Costume pieces shoes accessories and status

Also name the owner and the expected completion condition. If either is unknown, the work is not ready to enter the active queue.

## While the work is moving

- Update Build requirements by recital number and performer
- Update Collect music costume participation and program inputs
- Update Detect cross-number performer and quick-change conflicts
- Update Resolve venue volunteer and rehearsal dependencies
- Update Run dress-rehearsal checks and release the show-day plan

Every update should change a decision. Notes such as “followed up” are weak unless they also include the channel, result, next date, and owner.

## Before marking it complete

- Verify Rehearsal call venue and attendance
- Verify Performance order and quick-change window
- Verify Backstage volunteer prop and room assignment
- Verify Dress check exception owner and show release

Confirm that the actual outcome—not just an activity—has been recorded. If the process ended early, use a closed reason rather than deleting the record.

## Copy-and-paste weekly review

- [ ] Review records where a number performer or production input is added or changed
- [ ] Review records where the schedule creates a performer or backstage conflict
- [ ] Review records where dress rehearsal exposes a missing or incorrect dependency

- [ ] Check for tracking costume status only at class level
- [ ] Check for replacing a music file without version confirmation
- [ ] Check for scheduling consecutive numbers without performer-change review
- [ ] Check for assuming a parent message means every dependency is ready

## Make the checklist measurable

Choose one metric before the next cycle. Good options for this workflow are Ready-at-dress rate, Quick-change conflict age, Show-day exception rate. A checklist that never changes a metric or prevents a known failure mode is probably administrative overhead.

## Assign ownership and escalation

Put one role—not a group—next to every item that can remain open. Define a backup owner and an escalation time for work that affects a customer, client, participant, or delivery promise. During review, separate **not started**, **waiting on someone**, and **failed validation**; those states need different actions. If a checklist item repeatedly waits on the same dependency, redesign the intake or handoff instead of adding more reminder boxes.
