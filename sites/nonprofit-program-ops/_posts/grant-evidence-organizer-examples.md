Examples make nonprofit grant reporting evidence and outcome documentation easier to design because they reveal where a neat diagram meets messy work. The scenarios below are not claims about a particular company; they are test cases small nonprofit direct-service and program teams can run against a template or software trial.

### Scenario 1: Attendance evidence covers the program year but the grant asks for the quarter

Create the record before the first follow-up. Capture Grant and report period, Reporting question, Program or activity, then move it through map reporting questions and inventory available evidence. If a reporting question has no approved evidence, do not improvise in a private message; assign the exception, set a review date, and preserve the evidence needed for the next decision. Close with an explicit outcome and reason. ### Scenario 2: A participant quote lacks documented permission for external use

Create the record before the first follow-up. Capture Reporting question, Program or activity, Evidence type, then move it through map reporting questions and inventory available evidence. If an item contains sensitivity or permission uncertainty, do not improvise in a private message; assign the exception, set a review date, and preserve the evidence needed for the next decision. Close with an explicit outcome and reason. ### Scenario 3: Two spreadsheets use different definitions for program completion

Create the record before the first follow-up. Capture Program or activity, Evidence type, Source link, then move it through map reporting questions and inventory available evidence. If review finds a period, definition, or source mismatch, do not improvise in a private message; assign the exception, set a review date, and preserve the evidence needed for the next decision. Close with an explicit outcome and reason.

## Debrief each scenario

After running a scenario, ask:

- Did the record make start from the reporting question?
- Did the record make prefer the least sensitive evidence that answers it?
- Did the record make definitions and periods are recorded with the source?
- Did the record make a reviewer approves evidence before it enters the narrative?

Also check whether a new teammate could identify the owner, next action, and finish condition without opening another system.

## Convert scenarios into acceptance tests

Use the normal case, waiting case, and closed-without-completion case in every software demo. Require the vendor—or your own prototype—to show the full workflow rather than isolated feature screens. Export the resulting records and verify that the status history remains understandable.
