Examples make tutoring parent progress reporting workflow easier to design because they reveal where a neat diagram meets messy work. The scenarios below are not claims about a particular company; they are test cases independent tutoring centers and multi-tutor education businesses can run against a template or software trial.

### Scenario 1: A reading student has attendance logged but no skill evidence

Create the record before the first follow-up. Capture Student and program, Reporting period, Goal or skill area, then move it through define the reporting period and required evidence and collect structured tutor session notes. If a required session note is missing near publication, do not improvise in a private message; assign the exception, set a review date, and preserve the evidence needed for the next decision. Close with an explicit outcome and reason. ### Scenario 2: Two tutors use different names for the same algebra goal

Create the record before the first follow-up. Capture Reporting period, Goal or skill area, Session evidence and observation, then move it through define the reporting period and required evidence and collect structured tutor session notes. If multiple tutors record conflicting progress, do not improvise in a private message; assign the exception, set a review date, and preserve the evidence needed for the next decision. Close with an explicit outcome and reason. ### Scenario 3: A parent asks why the next focus changed from the previous report

Create the record before the first follow-up. Capture Goal or skill area, Session evidence and observation, Tutor author and submission time, then move it through define the reporting period and required evidence and collect structured tutor session notes. If a parent asks a question that needs tutor or director review, do not improvise in a private message; assign the exception, set a review date, and preserve the evidence needed for the next decision. Close with an explicit outcome and reason.

## Debrief each scenario

After running a scenario, ask:

- Did the record make every open parent progress update needs one owner and a next review time?
- Did the record make completion requires recorded evidence that each reporting period produces an approved, evidence-based parent update with clear progress and next focus?
- Did the record make automated reminders stop after verified completion or a documented closed reason?
- Did the record make keep tutoring schedule and student record system as the system of record; only necessary coordination data belongs here?

Also check whether a new teammate could identify the owner, next action, and finish condition without opening another system.

## Convert scenarios into acceptance tests

Use the normal case, waiting case, and closed-without-completion case in every software demo. Require the vendor—or your own prototype—to show the full workflow rather than isolated feature screens. Export the resulting records and verify that the status history remains understandable.
