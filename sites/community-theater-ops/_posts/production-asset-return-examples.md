Examples make theater prop and costume return tracking easier to design because they reveal where a neat diagram meets messy work. The scenarios below are not claims about a particular company; they are test cases community theaters and volunteer-led stage-production teams can run against a template or software trial.

### Scenario 1: A prop weapon transfers from props to stage management

Create the record before the first follow-up. Capture Production asset and inventory ID, Description components size and condition, Owner lender and storage origin, then move it through issue assets to a person production and purpose and record condition components and return rule. If an asset leaves controlled storage, do not improvise in a private message; assign the exception, set a review date, and preserve the evidence needed for the next decision. Close with an explicit outcome and reason. ### Scenario 2: A costume returns without one accessory

Create the record before the first follow-up. Capture Description components size and condition, Owner lender and storage origin, Issued to purpose date and deadline, then move it through issue assets to a person production and purpose and record condition components and return rule. If custody changes or return deadline passes, do not improvise in a private message; assign the exception, set a review date, and preserve the evidence needed for the next decision. Close with an explicit outcome and reason. ### Scenario 3: Borrowed microphones need lender confirmation after strike

Create the record before the first follow-up. Capture Owner lender and storage origin, Issued to purpose date and deadline, Custody transfers and acknowledgments, then move it through issue assets to a person production and purpose and record condition components and return rule. If inspection finds missing damaged or cleaning-required components, do not improvise in a private message; assign the exception, set a review date, and preserve the evidence needed for the next decision. Close with an explicit outcome and reason.

## Debrief each scenario

After running a scenario, ask:

- Did the record make every open production asset custody needs one owner and a next review time?
- Did the record make completion requires recorded evidence that every production asset has assigned custody, condition evidence, return deadline, storage destination, and an explicit lost damage repair or closed outcome?
- Did the record make automated reminders stop after verified completion or a documented closed reason?
- Did the record make keep the theater audition, cast, rehearsal, scene, volunteer, inventory, and production platform as the system of record; only necessary coordination data belongs here?

Also check whether a new teammate could identify the owner, next action, and finish condition without opening another system.

## Convert scenarios into acceptance tests

Use the normal case, waiting case, and closed-without-completion case in every software demo. Require the vendor—or your own prototype—to show the full workflow rather than isolated feature screens. Export the resulting records and verify that the status history remains understandable.
