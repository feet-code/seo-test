Examples make equipment rental return damage documentation easier to design because they reveal where a neat diagram meets messy work. The scenarios below are not claims about a particular company; they are test cases independent equipment, tool, and event-rental businesses can run against a template or software trial.

### Scenario 1: A returned lift has a bent guard not shown at checkout

Create the record before the first follow-up. Capture Contract, customer, and asset, Checkout condition and media, Return time, location, and inspector, then move it through check in the asset and freeze its availability state and compare return condition with checkout evidence. If an asset is returned with condition different from checkout, do not improvise in a private message; assign the exception, set a review date, and preserve the evidence needed for the next decision. Close with an explicit outcome and reason. ### Scenario 2: A camera kit comes back without one battery

Create the record before the first follow-up. Capture Checkout condition and media, Return time, location, and inspector, Meter, fuel, and consumable readings, then move it through check in the asset and freeze its availability state and compare return condition with checkout evidence. If a required accessory or meter reading is missing, do not improvise in a private message; assign the exception, set a review date, and preserve the evidence needed for the next decision. Close with an explicit outcome and reason. ### Scenario 3: A pressure washer is returned after hours with no fuel reading

Create the record before the first follow-up. Capture Return time, location, and inspector, Meter, fuel, and consumable readings, Damage description and photos, then move it through check in the asset and freeze its availability state and compare return condition with checkout evidence. If damage affects safety, availability, waiver coverage, or customer billing, do not improvise in a private message; assign the exception, set a review date, and preserve the evidence needed for the next decision. Close with an explicit outcome and reason.

## Debrief each scenario

After running a scenario, ask:

- Did the record make every open rental return inspection needs one owner and a next review time?
- Did the record make completion requires recorded evidence that every returned asset is inspected against checkout evidence and any damage decision is documented before billing or release?
- Did the record make automated reminders stop after verified completion or a documented closed reason?
- Did the record make keep rental contract, asset, billing, and maintenance system as the system of record; only necessary coordination data belongs here?

Also check whether a new teammate could identify the owner, next action, and finish condition without opening another system.

## Convert scenarios into acceptance tests

Use the normal case, waiting case, and closed-without-completion case in every software demo. Require the vendor—or your own prototype—to show the full workflow rather than isolated feature screens. Export the resulting records and verify that the status history remains understandable.
